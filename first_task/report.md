1.1 image stylization
    The stack used: TensorFlow, TensorFlow Hub, OpenCV.
    Advantages of the chosen solution: TensorFlow Hub provides pre-packaged, ready-to-use models. The Magenta model 
        allows you to perform style transfer on any reference image without the need for retraining.
    Operating principle and reasons for selection: the model uses an architecture that separates the representation of
        content and style in a latent space. The arbitrary-image-stylization-v1-256 version was selected because it 
        generates the result in a single forward pass. 
    Data structure: The model was trained on the MS-COCO dataset and WikiArt (for styles). For inference, two images are    
        required: a content image and a style image, normalized to the range [0, 1] with the addition of a batch dimension [1, H, W, 1].
    Quality metrics:
        ML metrics: FID (Fréchet Inception Distance) to assess visual similarity to the style while preserving the content structure.
        Infrastructure metrics: inference time per image.
    Implementation features: The code correctly handles the conversion of color spaces (RGB to BGR) for saving via OpenCV. 
        Using tf.newaxis ensures the correct tensor shape at the model input.

1.2. local llm
    Advantages of the chosen solution: Using the local API (Ollama) guarantees complete data privacy and no dependence 
        on external providers. 
    Operating principle and reasons for selection: The choice of version 7B is due to the optimal fact that it is placed in 8-16 GB of RAM
    Data structure: Input data: a JSON object containing a model (model ID), prompt (user's text request), and stream. 
        The model was trained on large-scale text corpora (Common Crawl, code from GitHub, scientific articles, multilingual 
        texts).  Output data: a JSON object from the API, from which the string value of the response field is extracted; 
        this field contains the text generated by the model.
    Quality metrics:
        ML metrics: Perplexity (perplexity), as well as evaluations on standard benchmarks.
        Infrastructure metrics: generation speed (tokens per second) and peak memory (RAM) or video memory (VRAM) consumption during inference.
    Implementation features: The code is extremely minimalist and efficient. Using the “stream”: False parameter means that the script blocks and waits for the entire response to be fully generated before outputting it.

1.3. picture analysis
    The stack used: PyTorch, Torch Hub, Ultralytics YOLOv5, pandas
    Advantages of the chosen solution: Integration of Ultralytics with PyTorch Hub allows you to download the model and 
        get ready-made tools for post-processing in two lines of code. Support for uploading images directly by URL.
    The principle of operation and the reasons for the choice: YOLOv5 divides the image into a grid and predicts bounding 
        boxes and class probabilities in one pass. The yolov5s (small) version is selected how is the optimal solution between speed and accuracy
    Data structure: The model is trained on the MS COCO dataset (80 classes of objects). An image is fed to the input, 
        and a DataFrame with the columns xmin, ymin, xmax, ymax, confidence, class, and name is formed at the output.
    Quality metrics: 
        ML metrics: mAP@0.5:0.95 (Mean Average Precision), Precision, Recall.
        Grocery stores/Infrastructure metrics: FPS (frames per second) when processing a stream.
    Implementation features: Using the method.pandas().xyxy[0] is a good solution because it immediately converts raw 
        tensors into a structured format.

1.4. text analysis
    The stack used: Hugging Face transformers.
    Advantages of the chosen solution: the pipeline abstraction hides the complexity of tokenization and working with tensors.
        The XLM-RoBERTa model is multilingual, which eliminates the need to connect different models for different languages.
    Working principle and reasons for selection: XLM-RoBERTa is a transformer trained using masked language modeling (MLM) on 100 languages. 
    Data structure: The model was trained on the CC-100 (Common Crawl) dataset. For inference, a regular string is passed 
        as input. The output is a list of dictionaries with keys label (language code, e.g., 'en' or 'ru') and score (probability from 0 to 1).
    Quality metrics: 
        ML metrics: Accuracy (exceeds 95%).
        Infrastructure metrics: API response time (in milliseconds).
    Implementation features and security: The code is extremely concise. A token is being used

1.5. text to speech
    The stack used: PyTorch, Torch Hub, Silero Models, SoundFile.
    Advantages of the chosen solution: Silero models are optimized to work even on low‑performance processors. 
    Operating principle and reasons for selection: Silero TTS (version v5) uses modern speech generation architectures. 
        It was selected due to the availability of Russian speech, the presence of different voices, and the fact that 
        no graphics processor or training is required; Minimalism and lack of dependencies.
    Data structure: The model was trained on large datasets (for example, M-AILABS or internal builds). The input consists 
        of: text (string), speaker identifier (speaker), and sampling rate (sample_rate). The output is a one‑dimensional 
        tensor with an audio signal.
    Quality metrics: 
        ML metrics: MOS (Mean Opinion Score) to assess the naturalness of the voice.
        Infrastructure metrics: RTF (Real-Time Factor) is the ratio of the audio generation time to the duration of the audio itself.
    Implementation features: explicit specification of put_accent=True and the use of the + symbol for stress.
